# Action Board × Talent 統合体験デモ

入口：[http://127.0.0.1:3000/action-board-demo](http://127.0.0.1:3000/action-board-demo)

## このサンプルで伝えること

Action Boardでのミッション達成・活動履歴にTalent Profileが加わると、活動の担当経験を本人確認付きのスキルへつなげられます。同じアプリのスタッフ画面から、そのスキルを使った検索・チーム編成へ進めます。

本家の完全な複製ではなく、公開ページと公開コードを参考に独立実装した統合提案です。白い角丸ナビゲーション、ミントグラデーション、中央のレベルカード、バッジ・ミッション達成状況・活動タイムライン・シーズン履歴の並びを参考にしました。

## 公式環境からの分離

- 公式サイトの公開トップと公開ユーザープロフィールは、デザイン確認のため読み取り専用で閲覧しました。ログインが必要な本人のアカウント画面は取得せず、公開ソースの `/settings/profile` を参照しました。公式Auth、Supabase、Slack、分析SDKには接続しません。
- 公式コード・画像・ロゴ・フォントはコピーせず、React・CSS・Lucideで画面を作成しました。
- すべて架空の人物・ミッション・ポイント・活動日程です。達成ボタンは公式への報告でも実活動への申込でもありません。
- 保存先は `.local/action-board-demo.json`。単独版の `.local/talent-v02.json` とv0.1から独立しています。
- APIは `/api/action-board-demo`。cookieも専用名・専用パスを使い、単独版のアカウント切替と混ざりません。
- APIはローカルホスト限定。統合デモ画面のCSPは接続・画像・フォント等を同一originに制限し、外部フレームを禁止します。検索エンジン向けnoindexも設定しています。

## 3〜5分のデモ手順

1. 初回は田中さんのサポーター画面です。ホームの「まちにポスターを届けよう」を開きます。
2. 「ポスター貼りを担当した」を選び、「デモの達成を記録する」を押します。
3. 150ポイントと活動履歴が増え、スキル候補が見つかります。この時点では公開プロフィールに未反映です。
4. 「見つかったスキルを確認」から根拠を確認し、「この内容で承認」を押します。
5. マイタレントの「わたしの得意・経験」に「ポスター貼り」が「活動実績」由来として加わります。
6. 「スタッフとして見る」に切り替え、「ポスター貼りをお願いできる人」で検索します。承認された人が選定理由付きで候補になります。
7. 「チームをつくる」で入力済みの横浜街宣の条件を使って編成します。9つの担当枠、選定理由、確認事項を表示します。候補案であり、参加確定や連絡送信はしません。

本家との見え方を比較するには、[マイページ](http://127.0.0.1:3000/action-board-demo/account)を開いてください。レベル・バッジ・ミッション達成状況・活動タイムライン・シーズン履歴を既存領域として表示し、その後ろにTalentのカードを追加しています。プロフィールカードの「アカウント設定」から[設定画面の配置例](http://127.0.0.1:3000/action-board-demo/settings)へ進めます。こちらも既存設定の後ろにTalentカードを置いています。設定内の既存項目は公式認証や個人情報に接続できないため、デモでは読み取り専用の見本です。Talent側の編集・推薦・候補承認は動作します。

公開ソースのアカウントメニュー構成を参考に、ヘッダー右端のアバターから「ホーム」「マイページ」「マイタレント」などを開けます。「マイタレント」は[本人用ページ](http://127.0.0.1:3000/action-board-demo/talent)に遷移します。ポスティングマップ等の公式機能はデモ内で未接続と明示しています。デモ用アカウント切替はヘッダーの外に配置しました。マイタレントのメニューカード・主要パネルも、マイページの白地、黒い縁取り、ミント色のアクセントに合わせています。

議員・党職員・エリアサポーターのアカウントを選ぶと、ホームを経由せず[サポーター検索](http://127.0.0.1:3000/action-board-demo/supporters)が開きます。アカウントメニューにもホームは表示しません。[チーム編成](http://127.0.0.1:3000/action-board-demo/team)、[活動管理](http://127.0.0.1:3000/action-board-demo/activities)を行き来できます。検索欄・条件パネル・人物カード・チーム案・活動カードは、本人用ページと同じ白地、黒い縁取り、ミント色のアクセントで表示します。

検索画面の「タグ・条件で探す」から「登録済みタグを見る」を押すと、架空プロフィールに現在登録されているタグがカテゴリ別に表示されます。タグを選ぶと絞り込み条件に追加できます。「明るい」「朗らか」「フッ軽」「ポスター奉行」など、人柄や活動で役立つ得意も含みます。42種類の追加例は架空の本人申告データです。プロフィールの編集画面でも、仕事・専門の経験からカジュアルな強みまで前向きな言葉で登録できることを案内しています。既存のローカル保存データには追加例を一度だけ補い、本人が編集・削除した内容を保持します。

「参加のみ・担当の記録なし」なら活動履歴とポイントだけを保存します。参加しただけでイベント運営などの能力を推測しません。同じミッションを再送信しても、ポイント・履歴・候補は重複しません。

AIインタビュー、プロフィール編集、政策への関心と助言分野・立場の登録、推薦、活動登録も統合画面内から操作できます。Slack風サンプル抽出は取り下げ、画面・実行APIを停止しています。実LLMやEmbeddingは未接続です。

「マイタレント」から「仲間の強みを推薦する」へ進むと、本人が承認済みの推薦スキルカードにサムアップと件数が表示されます。本人以外のサポーターやスタッフが、スキルへの共感や助けられた感謝として押せます。元の推薦者も押せます。再度押すと取り消せます。件数は検索順位や能力点数には使いません。ミッション、推薦、発見候補、検索などにはコードで描いたイラストを追加しました。

## 実際に統合するときの対応

| 本家の機能・データ | Talentの接続先 |
|---|---|
| Supabase Auth / public_user_profiles | 同じauth.users.idにTalent Profileと権限を追加 |
| achievements / missions / 明示された担当記録 | adapterでSkill Evidence・本人確認待ち候補へ変換 |
| マイページ・活動履歴 | スキル・経験・意欲・活動可能条件を横断表示 |
| アカウント設定 `/settings/profile` | 既存フォーム・ログイン設定・連携・退会の後に、独立したTalent管理導線を追加。既存フォームの保存処理は変更しない |
| スタッフ用の活動管理 | 承認済みスキルの検索と候補チーム作成 |

本家への組込時は `features/action-board-demo` のサンプル認証・保存先を置換します。`features/talent` のサービス・本人確認・DTO・Team Builderは共有しています。共通画面にはAPIクライアントを注入するため、単独版と統合版で処理を複製しません。推薦スキルへのサムアップは `supabase/migrations/202609240001_talent_skill_agreements.sql` にテーブル・RLS・RPC案を用意しましたが、公式環境には適用していません。

## 起動・検証

```bash
npm run dev
npm test
node scripts/verify-board-demo.mjs
```

統合デモ用HTTPチェックは42項目です。単体テストでは、達成→未承認→承認→検索のつながり、参加だけからの推測禁止、重複防止、権限、データ分離を確認しています。

2026-09-25の確認：全68テスト、統合デモHTTP42項目、既存版HTTP24項目、型検査・production buildが成功。ブラウザでも、ミッション達成→候補承認→活動実績としての反映→スタッフ検索と、9名のチーム案生成を通して確認しました。推薦同意の追加・再読込・取り消しも確認しました。マイページ・設定・ホームのデスクトップ表示と390px幅を目視確認し、横はみ出しがないことを確認しました。操作確認で森さんのポスター達成・承認とサンプルチーム案をデモ内に保存しました。

2026-09-27の追加確認：カジュアルなスキル例の登録、既存ローカルデータへの一度だけの補完、自然文検索を含む全73テスト、型検査・production buildが成功しました。
