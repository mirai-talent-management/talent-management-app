# Action Board × Talent 統合デモ

Action Boardでの活動から本人確認付きのスキルを育て、スタッフによる人材検索・チーム案作成につなげるアイデアを体験できるローカルプロトタイプです。18名の架空データを含みます。Action Board本体や本番データへの変更・接続はありません。

このデモはアイデア共有用のサンプルです。活用するかどうか、また活用する場合の画面・機能・実装方法は、チームの判断で自由に決められます。

## まず統合デモを開く

Node.js 24（24.14で検証）とnpmを使用します。

```bash
npm ci
npm run dev
```

[http://127.0.0.1:3000](http://127.0.0.1:3000) を開くと、[Action Board × Talent 統合デモ](http://127.0.0.1:3000/action-board-demo)へ自動で移動します。デモに環境変数やAPIキーは不要です。

初回はサポーターのデモアカウントで統合デモのホームが開きます。「スタッフとして見る」でスタッフ画面に切り替えられます。これは実ユーザーのログインではなく、架空アカウントを切り替えるデモです。

## 統合デモで体験できること

公開コードの画面構成を参考に、ミッション達成 → スキル候補 → 本人承認 → スタッフの検索・編成を同じアプリ内で体験できます。最初の操作は [統合デモの3〜5分の手順](docs/action-board-demo.md) を参照してください。

[本家に寄せたマイページ](http://127.0.0.1:3000/action-board-demo/account)では、レベル・バッジ・ミッション履歴などの後にTalentカードを追加。[アカウント設定の配置例](http://127.0.0.1:3000/action-board-demo/settings)でも既存項目の後にTalent導線を置きました。既存アカウント項目は公式サービスへ未接続の読み取り専用見本です。

統合デモの右上のアバターメニューにも「マイタレント」を追加しました。[マイタレント](http://127.0.0.1:3000/action-board-demo/talent)のカード・メニューは、マイページに合わせた白地・黒い縁取り・ミント色のデザインです。

スタッフ用の[サポーター検索](http://127.0.0.1:3000/action-board-demo/supporters)、[チーム編成](http://127.0.0.1:3000/action-board-demo/team)、[活動管理](http://127.0.0.1:3000/action-board-demo/activities)も同じデザインに揃え、画面間のメニューを追加しました。スタッフ用デモアカウントに切り替えて操作できます。

サポーターカードから開く詳細も、同じ白地・黒い縁取りのカードに揃えました。名前の下に主な得意分野を先に表示し、出典、活動意欲、参加条件、経験を見出しごとに確認できます。

公式環境には接続せず、保存先・API・cookieも単独版から分離しています。[操作手順と設計](docs/action-board-demo.md) を参照してください。

## 単独版 v0.2・旧版 v0.1

統合前の単独版 v0.2 は [サポーター一覧](http://127.0.0.1:3000/talent/supporters) から、旧版 v0.1 は [旧版ページ](http://127.0.0.1:3000/legacy) から開けます。どちらも統合デモとは別の入口です。

### 単独版 v0.2 を5分で試す

1. **サポーター一覧**：得意分野、本人申告／他者推薦／AI／活動実績の出典、活動意欲を確認。カードから詳細を開けます。
2. **自然文検索**：「横浜周辺で動画撮影ができて土曜午後に動ける人」「行政DXについて助言できる人」。条件と選定理由を確認。政策検索は本人が申告した関心・助言分野を区別します。従来のタグでも絞り込めます。
3. **AI Team Builder**：入力済みの横浜街宣の条件で案を作成。役割ごとの人員、根拠、未充足枠を確認。「検討済み」は参加確定ではありません。
4. 右上で最初のサポーター（田中さん）へ切替。**マイプロフィール**で自然文スキル、経験、活動可能条件・意欲、政策への関心・助言できる分野・助言の立場を編集。
5. **AIインタビュー**に「写真撮影が得意です」と回答し、深掘りを体験。「中断」後も再開できます。
6. **AI発見候補**でインタビュー・活動記録・推薦から生まれた候補の根拠と出典を確認し、表現を修正して承認、または却下。承認するまで公開スキルにはなりません。
7. **他者推薦**で別のサポーターに自由文を送り、相手のデモアカウントへ切り替えて候補を承認。
   承認済みの推薦スキルには、推薦者・本人以外のサポーターやスタッフが押せる「そう思う！😊」と同意人数も表示します。
8. スタッフの**活動登録**で活動・必要スキルを登録。詳細の連絡画面ではメール／Slack向け文面を作成・コピーできます（実送信なし）。

## 検討中の追加要素

- **非公開のチーム相性設定（Prefer Together / Prefer Avoid / Hard Avoid など）**：一方向の希望を編成の参考にする構想です。ただし、人間関係の摩擦や、チーム案を繰り返し試すことで相手へのNGが推測されるリスクがあります。本人・対象者への説明、権限、監査、照会制限、運用ルールを検討するまで、今回のデモでは画面・API・新規DBテーブルを提供せず、Team Builderにも反映しません。既存のローカルデモ保存データがある場合も参照しません。
- **Slack会話からのスキル発見**：Slack風文章のMock抽出を含め、今回のデモでは画面・実行APIを停止しました。任意の人が分析を繰り返して外部AIトークンを消費できる構成を避けるためです。将来検討する場合は、対象者の同意、実行権限、利用量・費用上限、レート制限、監査、候補の本人承認、機微情報の除外を先に設計します。既存のローカル保存データに残るSlack由来候補も表示・承認しません。
- Slack連絡先と、Slack DM向けの文面をコピーする機能は連絡導線として残します。会話の取得・分析やDMの実送信は行いません。
- Action Boardの実際の活動履歴と外部AIの接続は、同意と権限設計を整えた後に検討します。

政策の3項目はすべて本人の任意申告です。「関心」と「助言できる分野」を分け、助言の立場は自由文で記録します。資格・専門性の認証や、政策的立場のAI推定には使用しません。

## 実装とMockの境界

| 項目 | v0.2 | 将来接続 |
|---|---|---|
| 保存 | Node.jsサーバーの `.local/talent-v02.json` | Supabase repository |
| 認証 | 署名HttpOnly cookieのデモ切替、サーバーの本人／スタッフ検証 | Action BoardのSupabase SSR Auth |
| AI・面談 | ローカル辞書・ルール、本人承認、会話保存 | Structured Output provider |
| 自然文検索 | 条件解析、関連語・推薦・本人設定の意欲、理由表示 | Embedding・検索provider |
| Team Builder | 役割・人数、重複配置防止、活動条件を考慮 | 外部モデルによる要件構造化 |
| 活動実績 | 架空の活動記録、adapter契約 | 同意・権限付きAction Board連携 |
| Slack会話の分析 | 停止中（画面・APIなし） | 権限・費用制御を設計後に再検討 |
| 連絡 | テンプレート作成・コピー | 実送信API |

本物のLLMやEmbeddingは未接続で、画面にもMock表示があります。未知の表現や複雑な否定・日時表現には限界があります。活動意欲は本人が設定し、会話から推測しません。休止中の人は候補から除外します。

ローカル・架空データ専用です。公開ホストからのデモAPIを拒否し、productionでは標準で無効です。実運用にはSupabase認証・repositoryの接続と検証が必要です。

## 構成

- Next.js 15 App Router / React 19 / TypeScript / Tailwind CSS 4 / Lucide
- `src/app/`：ルートとAPI。`/` は統合デモへ移動し、`/talent/supporters` は単独版 v0.2、`/legacy` は旧版 v0.1
- `src/features/talent/components/`：画面と再利用UI
- `actions/`・`loaders/`：認証済み操作、公開DTO
- `services/`：抽出・正規化・面談・検索・チーム編成、provider契約
- `repositories/`・`adapters/`：保存先・Action Board活動記録の接続境界
- `server/`：セッション・入力検証・認証adapter
- `supabase/migrations/202609220001_talent_v02.sql`：追加テーブル・RLS・承認RPC（本番未適用）
- `supabase/migrations/202609240001_talent_skill_agreements.sql`：推薦スキル同意のテーブル・RLS・RPC案（本番未適用）
- `supabase/migrations/202609260001_talent_policy_advice.sql`：本人申告の政策助言項目案（本番未適用）

[Action Board比較・統合計画](docs/v02-action-board-integration.md)／[データ・権限設計](docs/v02-data-security.md)

## データ保存

統合デモは `.local/action-board-demo.json`、単独版 v0.2 は `.local/talent-v02.json` に保存し、どちらもGitには含めません。リセットはサーバーを停止し、対象ファイルをバックアップして削除すると、次回データ取得時にサンプルを再作成します。v0.1のlocalStorage／Supabaseとは分離しています。

再起動後にセッションが無効になった場合は「デモアカウントを選び直す」で復帰できます。必要なら `TALENT_DEMO_COOKIE_SECRET` を固定します。本物の認証には使用しません。

## 検証

```bash
npm test
npm run typecheck
npm run build
```

開発サーバーの `.next` を上書きせずビルドを確認する場合：

```bash
NEXT_DIST_DIR=.next-build npm run build
```

開発サーバー起動中のHTTP確認：

```bash
node scripts/verify-demo.mjs
```

70件のテストで旧版、候補承認、検索、チーム制約、情報分離、権限、Action Board adapter、推薦への同意と統合フローを確認。単独版HTTP確認は24項目、`node scripts/verify-board-demo.mjs` による統合デモ確認は42項目です。

productionビルドをローカルで試す場合だけ、`npm run build` 後に `TALENT_DEMO_ALLOW_PRODUCTION=true npm start` を使用します。公開環境向け設定ではありません。
