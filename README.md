# Action Board × Talent 統合デモ

Action Boardでの活動から本人確認付きのスキルを育て、スタッフによる人材検索・チーム案作成につなげるアイデアを体験できるローカルプロトタイプです。18名の架空データを含みます。Action Board本体や本番データへの変更・接続はありません。

アクションボードとの連携デモは、稲原さんが以前このアプリへの感想でアクションボードとの連携に言及したことを参考に制作しました。具体的な画面や機能は、このリポジトリで示す一案です。

このデモはアイデア共有用のサンプルです。活用するかどうか、また活用する場合の画面・機能・実装方法は、ご自由に決めて下さい。

現時点の本アプリの制作にはエンジニアが参加していません。READMEや設計資料にある技術的な説明の大部分はChatGPT 6によるものです。実際に活用する場合は、技術面も含めてチーム側で確認・判断してください。

## まず動画で見る

[主な5機能の紹介動画（MP4・約105秒）](docs/action-board-talent-5-features.mp4)では、実際に統合デモを操作した画面を使い、活動からスキル候補、マイタレントとインタビュー、仲間探し、チーム編成、連絡文作成を日本語の音声と画面テキストで紹介します。操作箇所が分かるよう、画面内にポインタとクリック表示を加えています。03「仲間探し」は、文章の入力から検索結果と候補の理由、プロフィールを開くところまでを一続きの操作映像で撮り直し、クリックの時刻とポインタの位置を合わせました。画面を読む時間を取り、ナレーションを操作の段階に合わせて分けています。場面によっては説明が先に終わり、無音のまま操作映像が続きます。画面の人物・活動は架空データです。動画内の検索・インタビュー・チーム編成はローカルのMockで、連絡も実際には送信しません。

## まず統合デモを開く

Node.js 24（24.14で検証）とnpmを使用します。

```bash
npm ci
npm run dev
```

起動ログに表示された `Local` のURLを開くと、統合デモへ自動で移動します。通常は [http://127.0.0.1:3000](http://127.0.0.1:3000) から [Action Board × Talent 統合デモ](http://127.0.0.1:3000/action-board-demo)へ移動します。デモに環境変数やAPIキーは不要です。

ブランチを切り替えた後などにトップページでサーバーエラーが出る場合は、起動中の開発サーバーをターミナルで `Ctrl+C` で止め、`npm run dev` で再起動してください。3000番が使用中なら別のポートで起動するため、その場合は起動ログの `Local` のURLを使用します。

初回はサポーターのデモアカウントで統合デモのホームが開きます。議員・党職員・エリアサポーターのデモアカウントに切り替えると、「活動に合う仲間を探す」画面が開きます。これは実ユーザーのログインではなく、架空アカウントを切り替えるデモです。

## 統合版ならではの体験

[Action Board × Talent 統合デモ](http://127.0.0.1:3000/action-board-demo)では、Action Board風のミッション達成 → 活動履歴 → スキル候補 → 本人承認 → スタッフの検索・編成を一つの画面構成で体験できます。実際のAction Boardには接続していません。最初の操作は[統合デモの3〜5分の手順](docs/action-board-demo.md)を参照してください。

[マイページ](http://127.0.0.1:3000/action-board-demo/account)では、レベル・バッジ・ミッション履歴などの後にTalentカードを配置。[アカウント設定の配置例](http://127.0.0.1:3000/action-board-demo/settings)と右上のアバターメニューからも[マイタレント](http://127.0.0.1:3000/action-board-demo/talent)へ進めます。既存アカウント項目は公式サービスに未接続の読み取り専用見本です。

スタッフ用デモアカウントではホームを経由せず「活動に合う仲間を探す」画面が開きます。統合版と単独版v0.2は、保存データ・API・セッションを分けています。[操作手順と設計](docs/action-board-demo.md)も参照してください。

## 統合版と単独版v0.2の共通機能

以下の機能は、統合版と単独版v0.2の両方で試せます。画面の見せ方やデモデータの保存先は異なります。

### プロフィールとAIインタビュー

本人は得意なこと、仕事・私生活・選挙・平時の経験、活動できる地域と時間、活動意欲を登録できます。政策への関心、助言できる分野、助言の立場も本人が任意で記入します。都道府県はAction Boardの登録情報から連携する想定で表示のみとし、市区町村は本人が自由記入します。ローカルデモでは都道府県も架空の値です。

AIインタビューでは「写真撮影が得意です」などの入力から経験を会話で振り返り、スキル候補を見つけます。途中で中断・再開できます。候補は根拠を見て表現を修正・承認または却下でき、承認するまで公開プロフィールに反映されません。AIはローカルルールによるMockです。

### サポーター検索とタグ

スタッフは、活動できる都道府県、名前・ふりがな、自然文、スキルや参加条件で候補を探せます。自然文検索では「横浜周辺で動画撮影ができて土曜午後に動ける人」などを入力でき、選定理由も表示します。プロフィール詳細では得意分野の出典、活動意欲、参加条件、経験を確認できます。

現在の自然文検索は外部AIを使わず、ローカルの辞書とルールで動くMockです。実際に活用する場合は、AIを使って言い換えや曖昧な条件も汲み取れる、より柔軟な検索にすることを提案します。検索対象は本人が登録・承認した情報を基本とし、候補の選定はスタッフが確認する想定です。

架空プロフィールには「明るい」「フッ軽」「ポスター奉行」「育児経験」「簿記経験」など42種類の例を追加しました。仕事や専門の経験に加え、人柄や日常の得意も前向きな表現で登録できるという提案です。「タグ・条件で探す」→「登録済みタグを見る」で一覧を確認し、タグを選んで絞り込めます。既存のローカルデモデータには例を一度だけ追加し、編集済みの内容は保持します。

デモは18人をローカルで検索します。約3万4千人規模の本番では、認証・権限を確認するサーバー側の検索、件数制限、ページ分けが必要です。

### チーム編成と活動管理

スタッフは活動内容と必要なスキルを登録し、AI Team Builderで役割・人数に合う候補チームを作れます。入力済みの横浜街宣の条件からも試せます。選定理由、参加前の確認事項、満たせなかった役割を表示します。「検討済み」は参加確定ではありません。

### 仲間の推薦とサムアップ

一緒に活動した仲間の強みを推薦できます。推薦されたスキルは本人が確認・承認してからプロフィールに反映されます。承認済みの推薦スキルには、本人以外の人が共感や感謝を伝えるサムアップを押せます。件数は能力の点数や検索順位には使いません。推薦する相手は都道府県と名前・ふりがなで探せます。

### 連絡文の作成

スタッフはサポーター検索やチーム案から人物詳細を開き、「メールで連絡」「Slackで連絡」を選べます。活動情報を含む文面の編集・コピーとデモ送信を試せます。デモ送信は画面上の確認のみで、実際には届きません。メールアプリやSlackを開く導線もありますが、架空の宛先は自動入力されません。

## 単独版と旧版

統合前の単独版v0.2は[サポーター一覧](http://127.0.0.1:3000/talent/supporters)から開けます。上記の共通機能を、Talent Management単独の画面で試す入口です。旧版v0.1は[旧版ページ](http://127.0.0.1:3000/legacy)から過去の形を確認できます。

## 検討中の追加要素

- **非公開のチーム相性設定（Prefer Together / Prefer Avoid / Hard Avoid など）**：一方向の希望を編成の参考にする構想です。ただし、人間関係の摩擦や、チーム案を繰り返し試すことで相手へのNGが推測されるリスクがあります。本人・対象者への説明、権限、監査、照会制限、運用ルールを検討するまで、今回のデモでは画面・API・新規DBテーブルを提供せず、Team Builderにも反映しません。既存のローカルデモ保存データがある場合も参照しません。
- **Slack会話からのスキル発見**：Slack風文章のMock抽出を含め、今回のデモでは画面・実行APIを停止しました。任意の人が分析を繰り返して外部AIトークンを消費できる構成を避けるためです。将来検討する場合は、対象者の同意、実行権限、利用量・費用上限、レート制限、監査、候補の本人承認、機微情報の除外を先に設計します。既存のローカル保存データに残るSlack由来候補も表示・承認しません。
- Slack連絡先と、Slack DM向けの文面作成・コピー・デモ送信を連絡導線として残します。会話の取得・分析やDMの実送信は行いません。
- Action Boardの実際の活動履歴と外部AIの接続は、同意と権限設計を整えた後に検討します。

政策の3項目はすべて本人の任意申告です。「関心」と「助言できる分野」を分け、助言の立場は自由文で記録します。資格・専門性の認証や、政策的立場のAI推定には使用しません。

## 実装とMockの境界

| 項目 | ローカルデモ | 将来接続 |
|---|---|---|
| 保存 | 統合版は `.local/action-board-demo.json`、単独版v0.2は `.local/talent-v02.json` | Supabase repository |
| 認証 | 署名HttpOnly cookieのデモ切替、サーバーの本人／スタッフ検証 | Action BoardのSupabase SSR Auth |
| 居住地域 | 架空の都道府県を表示し、市区町村だけ本人が入力 | 都道府県はAction Boardの `public_user_profiles.address_prefecture` を参照、市区町村はTalent側に保存 |
| AI・面談 | ローカル辞書・ルール、本人承認、会話保存 | Structured Output provider |
| 自然文検索 | ローカルの辞書・ルールによるMock検索、理由表示 | AIによる柔軟な条件解釈・Embedding検索（要設計・検証） |
| Team Builder | 役割・人数、重複配置防止、活動条件を考慮 | 外部モデルによる要件構造化 |
| 活動実績 | 統合版の架空の活動記録、adapter契約 | 同意・権限付きAction Board連携 |
| Slack会話の分析 | 停止中（画面・APIなし） | 権限・費用制御を設計後に再検討 |
| 連絡 | メール／Slackの文面作成・コピー・デモ送信、外部アプリを開く導線 | 実送信API |

本物のLLMやEmbeddingは未接続で、画面にもMock表示があります。未知の表現や複雑な否定・日時表現には限界があります。活動意欲は本人が設定し、会話から推測しません。休止中の人は候補から除外します。

ローカル・架空データ専用です。公開ホストからのデモAPIを拒否し、productionでは標準で無効です。実運用にはSupabase認証・repositoryの接続と検証が必要です。

## 構成

- Next.js 15 App Router / React 19 / TypeScript / Tailwind CSS 4 / Lucide
- `src/app/`：ルートとAPI。`/` は統合デモへ移動し、`/talent/supporters` は単独版 v0.2、`/legacy` は旧版 v0.1
- `src/features/talent/components/`：画面と再利用UI
- `actions/`・`loaders/`：認証済み操作、公開DTO
- `services/`：抽出・正規化・面談・検索・チーム編成、provider契約
- `repositories/`・`adapters/`：保存先・Action Board活動記録の接続境界
- `server/`：セッション・入力検証・認証adapter
- `supabase/migrations/202609220001_talent_v02.sql`：追加テーブル・RLS・承認RPC（本番未適用）
- `supabase/migrations/202609240001_talent_skill_agreements.sql`：推薦スキルへのサムアップのテーブル・RLS・RPC案（本番未適用）
- `supabase/migrations/202609260001_talent_policy_advice.sql`：本人申告の政策助言項目案（本番未適用）

## データ保存

統合デモは `.local/action-board-demo.json`、単独版 v0.2 は `.local/talent-v02.json` に保存し、どちらもGitには含めません。リセットはサーバーを停止し、対象ファイルをバックアップして削除すると、次回データ取得時にサンプルを再作成します。v0.1のlocalStorage／Supabaseとは分離しています。

再起動後にセッションが無効になった場合は「デモアカウントを選び直す」で復帰できます。必要なら `TALENT_DEMO_COOKIE_SECRET` を固定します。本物の認証には使用しません。

## 検証

```bash
npm test
npm run typecheck
npm run build
```

開発サーバーの `.next` を上書きせずビルドを確認する場合：

```bash
NEXT_DIST_DIR=.next-build npm run build
```

開発サーバー起動中のHTTP確認：

```bash
node scripts/verify-demo.mjs
```

77件のテストで旧版、候補承認、検索、チーム制約、情報分離、権限、Action Board adapter、推薦スキルへのサムアップ、居住地の都道府県を維持した市区町村編集、統合フローを確認。単独版HTTP確認は24項目、`node scripts/verify-board-demo.mjs` による統合デモ確認は42項目です。

productionビルドをローカルで試す場合だけ、`npm run build` 後に `TALENT_DEMO_ALLOW_PRODUCTION=true npm start` を使用します。公開環境向け設定ではありません。
